# GPTLasso

This repository houses the R package for multistudy multimodal transfer learning using **Global Pre-Training and Lasso (`GPTLasso`)**. It integrates Pretraining with Cooperative Learning to transfer multimodal knowledge from related source cohorts while maintaining target-specific behavior.

![](figures/gptlasso_workflow_TNR.png)

## Background

Modern biomedical prediction problems often involve multiple data modalities collected across several related cohorts, while each individual study may still be too small for stable model fitting. This project addresses that setting by combining multimodal modeling with transfer learning so that information can be shared across both studies and modalities while still allowing study-specific refinement.

The framework uses a pretrained multimodal model to learn shared structure, then fine-tunes study-level fits for improved local prediction. In simulations and motivating multi-omics applications, the goal is to improve predictive accuracy, estimation quality, and cross-study generalization relative to single-study or single-modal approaches.

**Keywords:** Transfer learning, Cooperative learning, Multistudy analysis, Multimodal Integration, Lasso, Pretraining

## Get Started

### Input containers

GPTLasso accepts either the legacy PCL-style list or a `MultiAssayExperiment`. The PCL form contains `feature_table`, `sample_metadata`, and `feature_metadata`. Its feature table is feature-by-sample; sample metadata contains `sample_id`, `study`, and `Y`; feature metadata contains `featureID` and a view column such as `featureType`. Metadata IDs must exactly match the corresponding feature-table dimnames and ordering.

For `MultiAssayExperiment` input, each named experiment is one view represented by a `SummarizedExperiment`; `colData(x)` contains `study` and `Y`; and `sampleMap(x)` maps experiment columns to primary samples. Every selected view must map exactly once to every primary sample. `assay.names` applies only to this format and must remain `NULL` for PCL input.

Training and prediction formats may be mixed because both are validated and converted to the same internal study-by-view layout.

**Note on `study` Labels:**

`gptLasso` detects study levels from `sample_metadata$study` for PCL input or `colData(x)$study` for MAE input. Unique values in observed order define the groups used for fitting and prediction summaries.

In this repository, `study` is the motivating example for handling different groups of data. In practice, users are welcome to define their own project-tailored grouping that serves the scientific or operational goal of the analysis.

### Packaged simulated data

The package contains deterministic Gaussian, binary, and survival datasets generated by `gen_simmba_multistudy()` and combined into ready-to-fit PCL objects. Each dataset contains matching training and test containers, the generating coefficients, and the simulation settings.

``` r
data(gaussianData, package = "GPTLasso")
data(binaryData, package = "GPTLasso")
data(survivalData, package = "GPTLasso")

names(gaussianData)
# [1] "x_train" "x_test" "true_betas" "settings"

gaussianData$settings[c("nsample", "rho.beta", "seed")]
```

The packaged datasets can be regenerated from `data-raw/generate_simulated_data.R`. The Gaussian tutorial data use three studies with 300, 200, and 100 samples before the 70/30 training-test split, seed 1234, and `rho.beta = 0.75`. The stronger cross-study coefficient sharing provides a stable prediction example without selecting a favorable random seed. The smaller binary and survival examples retain 60, 50, and 40 samples, `rho.beta = 0.5`, and seeds 5678 and 9012, respectively, to keep the software package compact.

### Tool

``` r
fit <- gptLasso(
    x,                                                      # PCL or MultiAssayExperiment
    assay.names = NULL,                                     # MAE assay selection; NULL for PCL
    target = NULL,                                          # Target study names or NULL for all studies
    alpha.ptlasso = 0.5,                                    # Transfer-learning level in [0, 1]
    family = c("gaussian", "binomial", "cox"),            # Response family
    type.measure = c("default", "mse", "auc", "deviance", "C"),
    rho = seq(0, 1, length = 11),                           # Multiview fusion parameter
    overall.lambda = c("lambda.1se", "lambda.min"),        # Overall-model lambda rule
    ind.lambda = c("lambda.1se", "lambda.min"),            # Individual-model lambda rule
    pre.lambda = c("lambda.1se", "lambda.min"),            # Pretrained-model lambda rule
    nfolds = 10,                                            # Number of cross-validation folds
    alpha.glmnet = 1                                        # Elastic-net mixing parameter
)
```

## Tutorial

This Gaussian example tutorial walks through packaged data inspection, model fitting, transfer-level tuning, prediction, and presentation of held-out results.

### 1. Load and inspect Gaussian multistudy multiview data

``` r
data(gaussianData, package = "GPTLasso")
x_train <- gaussianData$x_train
x_test <- gaussianData$x_test
```

Inspect the PCL layout before fitting:


The test PCL contains 90, 60, and 30 held-out samples from `Study_1`, `Study_2`, and `Study_3`, respectively. Feature identifiers and view ordering are identical across the two splits.

An MAE can be supplied instead, with named experiments, `study` and `Y` in `colData()`, and complete one-to-one `sampleMap()` entries. For example:

``` r
library(MultiAssayExperiment)
library(SummarizedExperiment)

mae_fit <- gptLasso(
  x = an_mae,
  assay.names = "value",
  family = "gaussian",
  rho = c(0, 0.5, 1)
)
```

### 2. Fit a multistudy multiview transfer-learning model with `cv.gptLasso()` targeting all studies

``` r
set.seed(2026)

cv_fit <- cv.gptLasso(
  x = x_train,
  target = NULL,
  family = "gaussian",
  type.measure = "mse",
  rho = c(0, 0.5, 1),
  alpha.ptlasso.list = seq(0, 1, 0.25),
  overall.lambda = "lambda.min",
  ind.lambda = "lambda.1se",
  pre.lambda = "lambda.1se",
  nfolds = 5,
  verbose = TRUE
)
```

**Note on fold construction for fitting models:**

When `foldid` is not specified, the algorithm automatically constructs V folds (i.e., `nfolds = V`) by partitioning samples within each study. The same within-study fold assignments are used consistently across both the individual models and the pretrained models. To fit the cooperative learning-based overall model, samples from the same fold across studies are stacked by view to form the V-fold training datasets.

### 3. Predict on held-out data

`predict()` automatically uses `x_test$sample_metadata$Y` when `ytest` is omitted. A model trained from PCL may be predicted with MAE data, and vice versa, provided the study, view, and feature layouts match.

``` r
pred <- predict(
  cv_fit,
  xtest = x_test,
  target = NULL,
  alpha.ptlasso = NULL,
  alpha.ptlasso.type = "varying",
  overall.lambda = "lambda.min",
  ind.lambda = "lambda.1se",
  pre.lambda = "lambda.1se",
  type = "response"
)
```

Inspect the prediction object, held-out performance, and selected support:

``` r
names(pred)
pred$metrics$MSE
pred$metrics$r2
c(
  overall = length(pred$supoverall),
  individual = length(pred$supind),
  common = length(pred$suppre.common)
)
```
